# Triển khai PWA cho wuDict (wudict-pwa)

> Phiên bản tài liệu: 24/11/2026. wuDict tham chiếu: `wuweidict/wudict`, bản mới nhất trong `changelog.txt` lúc viết là **v3.7.12**.
>
> Các chi tiết về wuDict trong tài liệu này lấy từ việc đọc mã nguồn (`internal/config/config.go`, `internal/server/routes.go`, `internal/server/auth.go`, `.github/workflows/build-purego.yml`). Những chỗ **chưa chạy thử** được đánh dấu **[cần kiểm chứng]**.

| Quyết định | Lựa chọn | Lý do |
|---|---|---|
| Fork hay project riêng | **Project riêng**, wuDict giữ nguyên | wuDict thay đổi gần như hằng ngày; sửa giao diện nhúng của nó sẽ xung đột liên tục |

## 1. Kiến trúc

```text
 Trình duyệt / PWA đã cài
          │  https://dict.example.com
          ▼
 ┌────────────────────┐
 │  Cloudflare edge   │  ← Cloudflare Access (đăng nhập), Cache Rules (bypass /api, /res)
 └─────────┬──────────┘
           │ tunnel (outbound từ VPS, không mở cổng)
 ┌─────────▼─────────────────────────────────────────────┐
 │ VPS / Docker                                           │
 │  ┌──────────────┐     ┌──────────────────────────────┐ │
 │  │ cloudflared  │────▶│ wudict-pwa (1 container)     │ │
 │  └──────────────┘     │  Caddy :8080                 │ │
 │                       │   ├─ /            → PWA tĩnh │ │
 │                       │   ├─ /api/* /res/* /setup …  │ │
 │                       │   │      → wuDict 127.0.0.1:6888│
 │                       │  wuDict (Go, purego)         │ │
 │                       │  /data  (volume)             │ │
 │                       │   ├─ dictionaries/  file từ điển│
 │                       │   ├─ db/            index SQLite│
 │                       │   └─ .wudict/       cấu hình, token│
 │                       └──────────────────────────────┘ │
 │  swap 2 GB trên host                                    │
 └────────────────────────────────────────────────────────┘
```

Vì sao Caddy nằm cùng container với wuDict: PikaPods và nhiều nền tảng tương tự chỉ chạy **một** image với một cổng. Với tự host, cũng chỉ cần thêm một container `cloudflared`.

## 3. Image Docker

### 3.1. `Dockerfile`

```dockerfile
# syntax=docker/dockerfile:1.7

############################
# 1) Build PWA
############################
FROM node:22-alpine AS pwa
WORKDIR /src
COPY pwa/package.json pwa/package-lock.json ./
RUN npm ci
COPY pwa/ ./
RUN npm run build            # xuất ra /src/dist

############################
# 2) Lấy binary wuDict từ release chính thức
############################
FROM alpine:3.20 AS wudict
ARG TARGETARCH                # amd64 | arm64, do buildx cung cấp
ARG WUDICT_VERSION            # ví dụ v3.7.12, do CI truyền vào
ARG WUDICT_REPO=PXDict/wudict
RUN apk add --no-cache curl
RUN set -eu; \
    if [ -z "${WUDICT_VERSION}" ]; then echo "Thiếu WUDICT_VERSION" >&2; exit 1; fi; \
    asset="wudict-linux-${TARGETARCH}-purego"; \
    url="https://github.com/${WUDICT_REPO}/releases/download/${WUDICT_VERSION}/${asset}"; \
    echo "Tải ${url}"; \
    curl -fsSL --retry 3 -o /wudict "${url}"; \
    test -s /wudict; chmod 0755 /wudict

############################
# 3) Runtime: Caddy + wuDict
############################
FROM caddy:2-alpine
ARG WUDICT_VERSION
RUN apk add --no-cache tini bash ca-certificates tzdata \
 && addgroup -S -g 1000 app && adduser -S -u 1000 -G app -h /data app \
 && mkdir -p /data /config/caddy && chown -R app:app /data /config

COPY --from=wudict /wudict /usr/local/bin/wudict
COPY --from=pwa    /src/dist /srv/pwa
COPY docker/Caddyfile     /etc/caddy/Caddyfile
COPY docker/entrypoint.sh /entrypoint.sh
RUN chmod 0755 /entrypoint.sh

# Cấu hình wuDict qua biến môi trường (thứ tự ưu tiên của wuDict:
# cờ CLI > biến môi trường > wudict.toml > mặc định).
ENV HOME=/data \
    XDG_CONFIG_HOME=/config \
    XDG_DATA_HOME=/config \
    DICT_DIR=/data/dictionaries \
    DB_DIR=/data/db \
    SERVER_IP=127.0.0.1 \
    SERVER_PORT=6888 \
    NO_BROWSER=1 \
    TRAY=0 \
    AUTH=on \
    INDEX_WORKERS=1 \
    PREVIEW_MEMORY=128MB \
    SEARCH_MEMORY=128MB \
    MORPH_CACHE=1 \
    MEMORY_LIMIT=400MB \
    WUDICT_VERSION=${WUDICT_VERSION}

LABEL org.opencontainers.image.title="wudict-pwa" \
      org.opencontainers.image.description="wuDict + PWA frontend" \
      org.opencontainers.image.licenses="GPL-3.0-or-later" \
      io.github.wudict.version="${WUDICT_VERSION}"

USER app
VOLUME ["/data"]
EXPOSE 8080
HEALTHCHECK --interval=30s --timeout=5s --start-period=30s --retries=3 \
  CMD wget -qO- http://127.0.0.1:8080/api/dicts >/dev/null || exit 1
ENTRYPOINT ["/sbin/tini", "--", "/entrypoint.sh"]
```

Ghi chú:
- **Không có checksum chính thức.** Workflow release của wuDict không công bố checksum cho binary, nên image tin vào TLS và GitHub. Nếu muốn tự kiểm soát hơn, thay giai đoạn 2 bằng build từ mã nguồn (mục 3.4).
- Image phát hành bản dùng lại binary GPL của wuDict, nên đặt nhãn `GPL-3.0-or-later` và ghi trong README nơi lấy mã nguồn wuDict (đường dẫn repo và tag). Tôi không phải luật sư, nếu có ý định thương mại thì cần xem kỹ hơn.

### 3.2. `docker/entrypoint.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail

: "${AUTH_TOKEN:?Cần đặt AUTH_TOKEN (chuỗi ngẫu nhiên, ví dụ: openssl rand -hex 32)}"
: "${PUBLIC_HOST:?Cần đặt PUBLIC_HOST, ví dụ dict.example.com}"

# wuDict chặn DNS rebinding bằng cách chỉ nhận Host header là IP, "localhost",
# hoặc tên nằm trong TRUSTED_HOSTS. Caddy chuyển nguyên Host gốc nên phải khai báo.
export TRUSTED_HOSTS="${TRUSTED_HOSTS:-[\"${PUBLIC_HOST}\"]}"

mkdir -p "${DICT_DIR}" "${DB_DIR}"
echo "wudict-pwa: wuDict ${WUDICT_VERSION:-unknown}, host ${PUBLIC_HOST}"

wudict serve &
WUDICT_PID=$!

caddy run --config /etc/caddy/Caddyfile --adapter caddyfile &
CADDY_PID=$!

shutdown() { kill -TERM "${WUDICT_PID}" "${CADDY_PID}" 2>/dev/null || true; }
trap shutdown TERM INT

# Một trong hai tiến trình chết → dừng cả container để Docker/PikaPods khởi động lại.
set +e
wait -n "${WUDICT_PID}" "${CADDY_PID}"
status=$?
set -e
shutdown
wait || true
exit "${status}"
```

### 3.3. `docker/Caddyfile`

```caddyfile
{
    admin off
    auto_https off          # TLS do Cloudflare đảm nhận
    persist_config off
}

:8080 {
    encode zstd gzip

    # 1) Đổi token lấy cookie: mở https://dict.example.com/?k=<AUTH_TOKEN> một lần.
    #    wuDict đặt cookie HttpOnly + SameSite=Strict rồi chuyển hướng về URL sạch "/",
    #    lúc đó Caddy trả PWA.  [cần kiểm chứng]
    @login query k=*
    handle @login {
        reverse_proxy 127.0.0.1:6888
    }

    # 2) Các đường dẫn thuộc wuDict (API, resource, trang quản trị gốc).
    @wudict path /api/* /res/* /style/* /files/* /assets/* /setup* /lemmas* /groups* /browse*
    handle @wudict {
        reverse_proxy 127.0.0.1:6888 {
            flush_interval -1        # cho SSE /api/ingest (tiến trình index)
        }
    }

    # 3) Còn lại là PWA.
    handle {
        root * /srv/pwa
        @nocache path /sw.js /registerSW.js /manifest.webmanifest /index.html
        header @nocache Cache-Control "no-cache"
        @hashed path /app-assets/*
        header @hashed Cache-Control "public, max-age=31536000, immutable"
        try_files {path} /index.html
        file_server
    }
}
```

**Xung đột đường dẫn cần tránh:** wuDict dùng `/assets/*` cho `frame.js`, `pick.js`... Vite mặc định cũng xuất file vào `/assets/`. Phải đổi thư mục build của Vite (mục 6.2: `build.assetsDir = "app-assets"`). `/favicon.ico` để PWA phục vụ.

## 4. Cấu hình wuDict trong container

| Biến | Giá trị trong image | Ý nghĩa |
|---|---|---|
| `SERVER_IP` / `SERVER_PORT` | `127.0.0.1` / `6888` | Chỉ Caddy trong container gọi được |
| `AUTH` | **`on`** | Xem cảnh báo bên dưới |
| `AUTH_TOKEN` | (bắt buộc, truyền lúc chạy) | Khóa truy cập; `openssl rand -hex 32` |
| `PUBLIC_HOST` | (bắt buộc) | Sinh `TRUSTED_HOSTS` |
| `DICT_DIR` / `DB_DIR` | `/data/dictionaries` / `/data/db` | File từ điển / từ điển đã index |
| `INDEX_WORKERS` | `1` | Mỗi lần index một từ điển |
| `PREVIEW_MEMORY` | `128MB` | Mặc định của wuDict là 1 GB, quá cao cho VPS nhỏ |
| `SEARCH_MEMORY` | `128MB` | Giới hạn RAM một lần tìm |
| `MORPH_CACHE` | `1` | Mỗi gói lemma tốn 7–65 MB |
| `MEMORY_LIMIT` | `400MB` | Trần **mềm** cho heap Go |
| `COMPRESSION` | (mặc định `zstd`) | Giữ nguyên, tiết kiệm đĩa nhất |

**Cảnh báo quan trọng về `AUTH`:** mặc định `AUTH = "auto"` chỉ đòi token khi wuDict nghe trên mạng. Trong image này wuDict nghe ở `127.0.0.1` và mọi request đều đến từ Caddy qua loopback. Để `auto` thì **toàn bộ API quản trị sẽ không cần token**. Vì vậy image đặt cứng `AUTH=on`.

## 5. Bảo mật: những gì token của wuDict không che

Trong `internal/server/auth.go`, danh sách `authFree` (các route **không cần token** ngay cả khi `AUTH=on`) gồm:

- `GET /api/dicts`, `GET /api/search`, `GET /res/...` (ba endpoint dành cho browser extension);
- `GET /api/openapi.yaml`;
- các trang giao diện (`/`, `/setup`, `/lemmas`, `/groups`) và file tĩnh của chúng.

Đây là thiết kế có chủ ý: dữ liệu quản trị (cài đặt, thư viện, xóa từ điển, yêu thích) vẫn cần token. Nhưng hệ quả là: **nếu đưa wuDict ra Internet chỉ với token, bất kỳ ai biết tên miền đều tra được từ điển của bạn và tải được resource** (bằng `curl`, không bị CORS cản). Với từ điển có bản quyền, hoặc chỉ đơn giản là muốn tránh bị quét, cần thêm một lớp phía trước:

**Cách khuyên dùng: Cloudflare Access** (Zero Trust → Access → Applications → Self-hosted)
- Ứng dụng: `dict.example.com`, toàn bộ đường dẫn.
- Policy: chỉ email của bạn (hoặc nhóm).
- **Session duration** dài (ví dụ 1 tháng) để PWA đã cài không bị đẩy ra trang đăng nhập liên tục.
- Nếu render mục từ trong iframe sandbox không cùng origin (mục 6.4), request `/res/` từ iframe có thể không mang cookie `CF_Authorization` (mặc định SameSite=Lax). Khi đó chỉnh thuộc tính SameSite của cookie trong cấu hình ứng dụng Access. **[cần kiểm chứng]**

**Cách thay thế (không dùng Cloudflare Access, ví dụ trên PikaPods):** thêm `basic_auth` vào Caddyfile cho mọi đường dẫn. Nhược điểm là PWA đã cài trên iOS xử lý basic auth kém.

Các lớp bảo vệ khác đã có sẵn:
- Cookie token của wuDict là `HttpOnly` + `SameSite=Strict`: script trong từ điển không đọc được cookie.
- Bộ chặn DNS rebinding dựa trên Host header (vì vậy phải có `TRUSTED_HOSTS`).
- Trần cấp phát bộ nhớ cho file từ điển hỏng hoặc độc hại (`MAX_*`, gói `internal/limits`).

Rủi ro còn lại: giao diện gốc của wuDict render mục từ trong iframe **cùng origin** (code tự ghi đây là "lớp tương thích, không phải sandbox"). Script độc trong một từ điển có thể gọi API bằng phiên của bạn. Biện pháp chính: **chỉ nạp từ điển từ nguồn tin cậy**.

## 6. Frontend PWA

### 6.1. Nguyên tắc

1. **Mọi lời gọi API nằm trong `pwa/src/api/wudict.ts`.** UI không gọi `fetch` trực tiếp. Khi wuDict đổi API chỉ phải sửa một chỗ.
2. **Kiểu dữ liệu sinh từ `openapi.yaml` của đúng phiên bản wuDict** trong image:
   ```bash
   # Lấy openapi.yaml theo đúng tag đang dùng
   curl -fsSL "https://raw.githubusercontent.com/PXDict/wudict/${WUDICT_VERSION}/internal/server/web/openapi.yaml" -o pwa/openapi.yaml
   npx openapi-typescript pwa/openapi.yaml -o pwa/src/api/schema.d.ts
   ```
   CI chạy lại bước này với tag mới. Nếu `tsc` báo lỗi nghĩa là API đã thay đổi theo cách làm hỏng PWA: build dừng, image cũ vẫn chạy.
3. Đường dẫn API của wuDict **không có tiền tố phiên bản** (`/api/...`, không phải `/api/v1/...`). Ngoài 3 endpoint dành cho extension, các endpoint khác phục vụ giao diện gốc nên có thể đổi bất kỳ lúc nào.

Các endpoint chính PWA sẽ dùng (chi tiết tham số xem `openapi.yaml`):

| Mục đích | Endpoint | Cần token |
|---|---|---|
| Danh sách từ điển | `GET /api/dicts` | Không |
| Tra từ | `GET /api/search?q=...&mode=...` | Không |
| Resource trong mục từ | `GET /res/{dict}/{path}` | Không |
| Gợi ý khi gõ | `GET /api/suggest` | Có |
| Nhóm từ điển | `GET/PUT /api/groups` | Có |
| Yêu thích | `GET/POST/DELETE /api/words` | Có |
| Duyệt, từ ngẫu nhiên | `GET /api/browse`, `GET /api/random` | Có |
| Cài đặt | `GET/PUT /api/prefs` | Có |

Cookie token đi kèm tự động vì cùng origin. Trong `fetch` đặt `credentials: "same-origin"` (mặc định của trình duyệt).

### 6.2. `pwa/vite.config.ts`

```ts
import { defineConfig } from "vite";
import { VitePWA } from "vite-plugin-pwa";

// Các đường dẫn thuộc wuDict: service worker KHÔNG được trả index.html cho chúng.
const WUDICT_PATHS = [/^\/api\//, /^\/res\//, /^\/style\//, /^\/files\//,
                      /^\/assets\//, /^\/setup/, /^\/lemmas/, /^\/groups/, /^\/browse/];

export default defineConfig({
  build: { assetsDir: "app-assets" },      // tránh đụng /assets/* của wuDict
  server: {
    proxy: {                                // dev: trỏ vào wuDict chạy local
      "^/(api|res|style|files|assets)/": "http://127.0.0.1:6888",
    },
  },
  plugins: [
    VitePWA({
      registerType: "prompt",               // hỏi người dùng trước khi cập nhật bản mới
      manifest: {
        name: "Từ điển",
        short_name: "Từ điển",
        start_url: "/",
        scope: "/",
        display: "standalone",
        theme_color: "#1f2937",
        background_color: "#ffffff",
        icons: [
          { src: "/icons/192.png", sizes: "192x192", type: "image/png" },
          { src: "/icons/512.png", sizes: "512x512", type: "image/png" },
          { src: "/icons/maskable-512.png", sizes: "512x512", type: "image/png", purpose: "maskable" },
        ],
        // Chọn chữ ở app khác → Chia sẻ → Từ điển  (Android)
        share_target: {
          action: "/",
          method: "GET",
          params: { title: "title", text: "q", url: "url" },
        },
      },
      workbox: {
        navigateFallback: "/index.html",
        navigateFallbackDenylist: WUDICT_PATHS,
        runtimeCaching: [
          {
            // Kết quả tra: ưu tiên mạng, mất mạng thì dùng bản đã cache
            urlPattern: ({ url }) => url.pathname === "/api/search" || url.pathname === "/api/suggest",
            handler: "NetworkFirst",
            options: {
              cacheName: "lookups",
              networkTimeoutSeconds: 4,
              expiration: { maxEntries: 500, maxAgeSeconds: 60 * 60 * 24 * 30 },
              cacheableResponse: { statuses: [200] },
            },
          },
          {
            // Ảnh, CSS, audio trong mục từ
            urlPattern: ({ url }) => url.pathname.startsWith("/res/"),
            handler: "CacheFirst",
            options: {
              cacheName: "dict-res",
              expiration: { maxEntries: 1500, maxAgeSeconds: 60 * 60 * 24 * 30, purgeOnQuotaError: true },
              cacheableResponse: { statuses: [200] },
            },
          },
          {
            // Danh sách từ điển
            urlPattern: ({ url }) => url.pathname === "/api/dicts",
            handler: "StaleWhileRevalidate",
            options: { cacheName: "meta" },
          },
          // Mọi endpoint khác (prefs, words, library, intake...) không cache.
        ],
      },
    }),
  ],
});
```

Giới hạn của chế độ offline: PWA chỉ xem lại được **những từ đã tra** khi có mạng. Muốn tra từ mới khi offline thì phải đưa cả file từ điển xuống máy (ví dụ OPFS + js-mdict), không nằm trong phạm vi tài liệu này.

### 6.3. Đăng nhập lần đầu

1. Cloudflare Access hỏi email và gửi mã OTP.
2. Mở `https://dict.example.com/?k=<AUTH_TOKEN>` một lần trên mỗi thiết bị. wuDict đặt cookie và chuyển hướng về `/` (PWA).
3. Cài PWA ("Thêm vào màn hình chính").

Trên iOS, PWA đã cài có kho cookie **riêng** với Safari. Có thể phải làm lại bước 2 **bên trong** PWA. Cách đơn giản: trong PWA có ô "Nhập khóa truy cập", khi gửi thì điều hướng tới `/?k=...`. **[cần kiểm chứng]**

### 6.4. Hiển thị mục từ

Có hai lựa chọn:

| | A. Giống wuDict (iframe `srcdoc` + `allow-same-origin`) | B. Iframe sandbox opaque-origin (`sandbox="allow-scripts"`) |
|---|---|---|
| Tương thích với từ điển MDX có JS/CSS | Cao (giống giao diện gốc) | Thấp hơn: không đo được chiều cao trực tiếp, phải dùng `postMessage` |
| Cách ly script độc | Không | Có |
| `/res/` | Hoạt động | Hoạt động vì `/res/` không cần token, nhưng xem lưu ý Cloudflare Access ở mục 5 |

Khuyên bắt đầu với **A**, tham khảo cách `internal/server/web/frame.js` của wuDict xử lý: chặn link nội bộ, phát audio, đồng bộ chiều cao. Chuyển sang **B** khi PWA đã ổn định.

## 7. Tự động cập nhật wuDict mới nhất

### 7.1. `scripts/latest-wudict.sh`

```bash
#!/usr/bin/env bash
# In ra tag release wuDict mới nhất (bỏ qua draft và pre-release),
# chỉ khi release có đủ binary linux amd64 và arm64. Thiếu thì thoát lỗi để CI giữ image cũ.
set -euo pipefail

REPO="${WUDICT_REPO:-PXDict/wudict}"
auth=()
[ -n "${GH_TOKEN:-}" ] && auth=(-H "Authorization: Bearer ${GH_TOKEN}")

json="$(curl -fsSL --retry 3 \
  -H "Accept: application/vnd.github+json" "${auth[@]}" \
  "https://api.github.com/repos/${REPO}/releases/latest")"

tag="$(jq -r '.tag_name' <<<"${json}")"
[ -n "${tag}" ] && [ "${tag}" != "null" ] || { echo "Không đọc được tag mới nhất của ${REPO}" >&2; exit 1; }

for arch in amd64 arm64; do
  name="wudict-linux-${arch}-purego"
  if ! jq -e --arg n "${name}" '.assets[] | select(.name == $n)' <<<"${json}" >/dev/null; then
    echo "Release ${tag} thiếu asset ${name}" >&2
    exit 1
  fi
done

echo "${tag}"
```

Tên asset `wudict-linux-<arch>-purego` lấy từ `build-purego.yml` của wuDict (biến `BINARY`). Nếu tác giả đổi cách đặt tên, script sẽ báo lỗi rõ ràng thay vì build ra image hỏng.

## 9. Swap và bộ nhớ (ưu tiên khi index từ điển lớn)

### 9.1. Vì sao cần swap

Theo tài liệu cấu hình của wuDict:
- Từ điển **đã index** trả lời từ đĩa (SQLite), nên RAM lúc chạy ổn định thấp.
- **Lúc index**, mỗi headword tốn "vài trăm byte". Ước tính với khoảng 300 B/headword: 1 triệu headword ≈ 300 MB; vài triệu bài ZIM Wikipedia ≈ trên 1,5 GB.

Swap biến trường hợp vượt RAM từ "bị OOM killer giết" thành "index chậm hơn". Đây là đánh đổi hợp lý vì index chỉ chạy một lần cho mỗi từ điển.

### 9.2. `scripts/setup-swap.sh`

```bash
#!/usr/bin/env bash
# Bật swapfile trên host (chạy bằng root). Mặc định 2G.  Dùng: sudo bash setup-swap.sh 2G
set -euo pipefail

SIZE="${1:-2G}"
SWAPFILE="${SWAPFILE:-/swapfile}"

[ "$(id -u)" -eq 0 ] || { echo "Cần chạy bằng root" >&2; exit 1; }

if swapon --show=NAME --noheadings | grep -qx "${SWAPFILE}"; then
  echo "Swap ${SWAPFILE} đã bật:"; swapon --show; exit 0
fi

echo "Tạo ${SWAPFILE} (${SIZE})..."
if ! fallocate -l "${SIZE}" "${SWAPFILE}" 2>/dev/null; then
  # fallocate không dùng được trên một số filesystem (vd. btrfs, một số loại ext) → dùng dd
  count_mb=$(( ${SIZE%G} * 1024 ))
  dd if=/dev/zero of="${SWAPFILE}" bs=1M count="${count_mb}" status=progress
fi
chmod 600 "${SWAPFILE}"
mkswap "${SWAPFILE}"
swapon "${SWAPFILE}"

grep -q "^${SWAPFILE} " /etc/fstab || echo "${SWAPFILE} none swap sw 0 0" >> /etc/fstab

# Chỉ dùng swap khi thật sự cần; giữ cache inode/dentry lâu hơn (SQLite đọc file nhiều)
cat > /etc/sysctl.d/99-wudict-swap.conf <<'EOF'
vm.swappiness=10
vm.vfs_cache_pressure=50
EOF
sysctl --system >/dev/null

swapon --show
free -h
```

### 9.3. Kiểm tra Docker có cho container dùng swap không

```bash
docker info 2>&1 | grep -i swap
```

Nếu thấy `WARNING: No swap limit support`, kernel chưa bật swap accounting cho cgroup. `memswap_limit` khi đó không có tác dụng, nhưng container vẫn có thể dùng swap của host. Phần lớn bản phân phối mới dùng cgroup v2 thì không gặp vấn đề này.

### 9.4. Ba lớp giới hạn bộ nhớ

| Lớp | Đặt ở đâu | Tác dụng |
|---|---|---|
| `MEMORY_LIMIT=400MB` | env của wuDict | Trần **mềm**: Go dọn rác mạnh hơn và bỏ cache thay vì phình to |
| `mem_limit: 768m` | compose | Trần **cứng** RAM của container |
| `memswap_limit: 2560m` | compose | RAM + swap tối đa; phần vượt `mem_limit` đi vào swap |

Gợi ý theo VPS:

| VPS | `mem_limit` | `memswap_limit` | swap host | `MEMORY_LIMIT` |
|---|---|---|---|---|
| 1 GB RAM | 768m | 2560m | 2G | 400MB |
| 2 GB RAM | 1536m | 3584m | 2G | 1GB |

### 9.5. Từ điển rất lớn: index ở máy khác rồi chép lên

Áp dụng khi index trên VPS quá chậm, hoặc khi chạy trên PikaPods (không bật được swap):

```bash
# Trên máy cá nhân nhiều RAM, dùng đúng image (cùng phiên bản wuDict với server)
docker run --rm -it \
  -e AUTH_TOKEN=local -e PUBLIC_HOST=localhost \
  -e INDEX_WORKERS=auto -e PREVIEW_MEMORY=4GB -e MEMORY_LIMIT=0 \
  -v "$PWD/data:/data" -v "$PWD/dicts:/data/dictionaries" \
  --entrypoint wudict ghcr.io/OWNER/wudict-pwa:wudict-v3.7.12 ingest --help
# → đọc trợ giúp của lệnh "ingest" rồi chạy với thư mục từ điển

# Chép từ điển gốc và kết quả index lên server
rsync -avP dicts/      vps:/srv/dictionaries/
rsync -avP data/db/    vps:/opt/wudict-pwa/data/db/
```

Phải dùng **cùng phiên bản wuDict**. Mỗi định dạng có "reader version"; index tạo bởi phiên bản khác sẽ bị đánh dấu lỗi thời và có thể bị index lại trên server. Cú pháp chính xác của lệnh `ingest`, và việc wuDict nhận ngay thư mục `db/` chép từ máy khác, **[cần kiểm chứng]** với một từ điển nhỏ trước.

## 10. Tự động cập nhật trên server tự host

### 10.1. `scripts/server-update.sh`

```bash
#!/usr/bin/env bash
# Kéo image mới, khởi động lại nếu có thay đổi, dọn image cũ.
set -euo pipefail
cd /opt/wudict-pwa

before="$(docker compose images -q app 2>/dev/null || true)"

if [ "${before}" != "${after}" ]; then

  done
  echo "Trạng thái: ${state}"
fi
docker image prune -f >/dev/null
```

## 11. PikaPods

**Thực tế cần biết:** PikaPods chạy ứng dụng từ **danh mục của họ**, không cho người dùng tự chạy một image bất kỳ. Ứng dụng muốn được đưa vào danh mục phải được đề xuất và bỏ phiếu trên trang feedback. Tiêu chí gồm: giấy phép cho phép tự host, không cạnh tranh với dịch vụ hosting trả phí của chính tác giả, và có image Docker chính thức hoặc bán chính thức (theo FAQ của PikaPods: docs.pikapods.com/faq và docs.pikapods.com/faq/apps).

Hệ quả:
- Image `wudict-pwa` cá nhân **khó được chấp nhận** vì không phải image chính thức của wuDict.
- Hướng khả thi: đề nghị tác giả wuDict phát hành image chính thức (có thể gửi chính Dockerfile này làm PR), sau đó đề xuất wuDict lên PikaPods. Nếu tác giả đồng ý nhận PWA vào upstream, PikaPods sẽ có luôn PWA.
- Trên PikaPods không bật được swap. Chọn gói RAM đủ cho lần index lớn nhất, hoặc index ở máy khác rồi tải `db/` lên (mục 9.5).
- Không dùng được Cloudflare Access trên tên miền mặc định của PikaPods, nên bảo vệ bằng `basic_auth` trong Caddy (mục 5).

Image trong tài liệu này **đã được thiết kế sẵn theo kiểu PikaPods**: một container, một cổng (8080), một volume (`/data`), cấu hình hoàn toàn bằng biến môi trường. Nếu sau này có kênh chạy image tùy chỉnh (PikaPods hoặc dịch vụ tương tự như Fly.io, Railway), không cần sửa gì.
