# 0004. TypeScript gateway with Better Auth

- Status: accepted
- Date: 2026-11-24
- Supersedes: the "Go" part of [ADR 0001](0001-gateway-replaces-caddy.md) (a gateway still replaces Caddy)

## Context

ADR 0001 put a hand-written Go service in front of wuDict. Phase 1 scaffolded it, and the plan had it
implement every part of authentication itself: password hashing, sessions, CSRF, rate limiting, invites
and user administration. Two things changed:

- PXDict must **manage its own users and offer several ways to sign in** (password, passkeys, social
  and OIDC providers, email links/codes, two-factor). Writing each method by hand is a lot of
  security-sensitive code to own.
- The PWA is already TypeScript. A second language doubles the toolchains, linters, CI jobs and
  dependency update flows, and the API types have to cross the language boundary through OpenAPI.

wuDict itself is unaffected: it stays the unmodified upstream Go binary, built from source
([ADR 0002](0002-build-wudict-from-source.md)), reached only over loopback HTTP. The gateway's
language is independent of it.

Options considered:

1. **Keep Go and hand-write auth** (plus `x/oauth2`, `go-oidc`, `go-webauthn`): smallest RAM, most
   code to own.
2. **Go with PocketBase as a framework:** users, OAuth2, OTP and MFA built in, plus an admin
   dashboard. No passkeys or magic links; pre-1.0 with breaking changes; still two languages.
3. **TypeScript with Better Auth (chosen).**

## Decision

- `pxdict-gateway` is written in **TypeScript** and runs on **Node.js 26 LTS**, using **Hono** with
  `@hono/node-server`. Its responsibilities do not change: it is the only entry point, serves the PWA,
  serves `/app-api`, and proxies an allowlist of wuDict routes with the token injected server-side.
- The repository becomes one **npm workspace**: `shared/` (types and zod schemas used by both sides,
  plus wuDict's generated types), `gateway/` and `pwa/`. One lockfile, one ESLint config, one CI job.
- **Authentication uses [Better Auth](https://www.better-auth.com/)**, mounted at `/app-api/auth/*`.
  It owns users, accounts, sessions, rate limiting and the CSRF/origin checks on its own routes. Sign-in
  methods, each enabled by configuration:
  - email or username + password (`username` plugin);
  - passkeys / WebAuthn (`@better-auth/passkey`);
  - social providers: Google, GitHub, Microsoft, Apple, Discord, … (enabled when their client ID and
    secret are set);
  - any OpenID Connect provider, e.g. Authentik, Keycloak, Zitadel or Authelia (`generic-oauth`);
  - magic links and email one-time codes (`magic-link`, `email-otp`), only when SMTP is configured;
  - TOTP two-factor authentication as a second factor (`two-factor`);
  - roles, banning, session revocation and impersonation for admins (`admin` plugin).
- **Storage:** SQLite through `better-sqlite3` (WAL), queried with **Drizzle ORM**; migrations are SQL
  files generated by `drizzle-kit`. Better Auth uses the same database through its Drizzle adapter.
- **Validation and API types:** zod 4 schemas in `shared/` are the contract for `/app-api`. The gateway
  validates with them and the PWA imports their inferred types. `gateway/openapi.yaml` is dropped. wuDict's
  types are still generated from its `openapi.yaml` at the pinned tag.
- **Build:** the gateway is bundled with esbuild into one ES module. Native modules (`better-sqlite3`)
  stay external and are installed in the image.
- **Cloudflare Access is not part of PXDict.** PXDict accounts are the only login layer; the Cloudflare
  tunnel remains a deployment option.

## Consequences

- One language and toolchain across the repo. Request/response types are shared directly instead of
  generated from an OpenAPI file.
- Much less security-sensitive code to write and review. In exchange, PXDict depends on Better Auth's
  release cadence and defaults; the version is pinned and upgrades are reviewed like code.
- Differences from the previous security rules, accepted and reflected in `AGENTS.md` §6:
  - passwords are hashed with **scrypt** (Better Auth's default, OWASP-acceptable) instead of argon2id;
  - Better Auth stores session tokens in its `session` table **as-is** (the cookie value is HMAC-signed
    with `BETTER_AUTH_SECRET`), not as a hash. The database and its backups must be protected
    accordingly;
  - CSRF protection relies on `SameSite=Lax` cookies plus an **Origin / `Sec-Fetch-Site` check** on
    every state-changing request (Better Auth's own check on its routes, the same middleware on PXDict's
    routes) instead of a per-session CSRF header.
- RAM: Node.js costs about 50–80 MB at idle, versus about 20–40 MB for the Go service. On a 1 GB VPS this
  still fits next to wuDict (about 50 MB idle, 260–300 MB while indexing) with swap; the V8 heap is capped
  in the image.
- The image grows by about 50–100 MB for the Node.js runtime.
- Better Auth's table names and endpoint shapes are set by the library; PXDict's own tables reference its
  `user.id` (text).
- The Phase 1 Go skeleton is removed; its design (config variables, route allowlist, header stripping,
  `/api/dicts` filtering) carries over to the TypeScript gateway through the plan.
