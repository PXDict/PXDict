# PXDict — Phased implementation plan

> Written: 2026-11-24. Reference wuDict version: **v3.7.11** (latest stable tag; v3.7.12 is only a
> pre-release — see [wudict-notes.md](wudict-notes.md)). wuDict behaviour this plan relies on is verified in
> [`wudict-notes.md`](wudict-notes.md).
> Baseline: the [original design](design/wudict-pwa.md) (single user). This plan keeps the packaging,
> CI and deployment parts of that design and adds **user management, login, per-user data, dictionary
> proposals with admin review, and storage administration**.
> Working rules: see [`AGENTS.md`](../AGENTS.md).

---

## 0. Changes from the original design

| Topic | Original design | PXDict | Why |
|---|---|---|---|
| Process in front of wuDict | Caddy | **pxdict-gateway (TypeScript, Node.js + Hono)** | Needs logic: sessions, roles, per-user data, uploads. The gateway also serves static files, so Caddy is dropped ([ADR 0001](adr/0001-gateway-replaces-caddy.md), [ADR 0004](adr/0004-typescript-gateway-better-auth.md)) |
| Login | Cloudflare Access + `/?k=<AUTH_TOKEN>` | **PXDict accounts managed by the gateway** with several sign-in methods via Better Auth: password (email or username), passkeys, social providers (Google, GitHub, Microsoft, Apple, Discord, …), any OIDC provider, magic link / email code, optional TOTP two-factor. **No Cloudflare Access** | Multiple users; users must not know wuDict's token; no third-party login gate |
| wuDict token | Browser cookie | **Held only by the gateway**, injected when proxying | Prevents users from calling wuDict admin APIs |
| `TRUSTED_HOSTS` | Required | Not needed | Gateway sends `Host: 127.0.0.1:6888` |
| Favorites, groups, settings | wuDict `/api/words`, `/api/groups`, `/api/prefs` | **Per-user tables in the gateway** | wuDict APIs are global |
| Entry rendering | Style A (same-origin iframe) first | **Style B (sandbox) by default**, A only for `trusted` dictionaries | User-proposed dictionaries + admin sessions on the same origin |
| Image name | `wudict-pwa` | `pxdict` (`IMAGE_NAME` in CI) | Repository name |

Also changed after Phase 0: the wuDict binary is **built from source** (purego) at a pinned stable tag,
because releases publish only glibc-linked `-cgo` binaries ([ADR 0002](adr/0002-build-wudict-from-source.md)).
After Phase 1 the gateway moved from Go to **TypeScript** so the whole repo is one language and
authentication comes from a maintained library ([ADR 0004](adr/0004-typescript-gateway-better-auth.md)).

Unchanged: one multi-arch image on GHCR, one port 8080, one volume `/data`,
cloudflared tunnel (optional, TLS only), swap + memory limits, CI auto-detecting new wuDict releases,
systemd auto-update timer.

## 1. Data model (gateway SQLite at `/data/gateway/pxdict.db`)

**Owned by Better Auth** (schema generated by its CLI into Drizzle; do not edit by hand). Field names
are Better Auth's; plugins add the marked columns/tables:

```sql
user(id TEXT, name, email UNIQUE, emailVerified, image, createdAt, updatedAt,
     username UNIQUE, displayUsername,                       -- username plugin
     role, banned, banReason, banExpires,                    -- admin plugin ('user' | 'admin')
     twoFactorEnabled)                                       -- two-factor plugin
session(id, userId, token UNIQUE, expiresAt, ipAddress, userAgent, impersonatedBy, createdAt, updatedAt)
account(id, userId, providerId, accountId, password /* scrypt hash for 'credential' */,
        accessToken, refreshToken, idToken, expiresAt…, scope, createdAt, updatedAt)
verification(id, identifier, value, expiresAt, …)          -- email links/codes, OAuth state
passkey(id, userId, name, publicKey, credentialID, counter, deviceType, backedUp, transports, …)
twoFactor(id, userId, secret, backupCodes)
rateLimit(id, key, count, lastRequest)                      -- storage: "database"
```

**Owned by PXDict** (Drizzle schema in `gateway/src/db/schema.ts`, migrations in `gateway/drizzle/`;
`user_id` columns reference `user.id`):

```sql
invites(id, code_hash UNIQUE, created_by, role, note, expires_at, used_at, used_by, created_at)  -- REGISTRATION=invite

user_settings(user_id PRIMARY KEY, history_enabled, history_retention_days /* 0 = forever */,
              default_mode, ui_lang /* NULL = device */, theme, font_size, updated_at)
search_history(id, user_id, query, mode, dict_ids_json /* PXDict ids, NULL = enabled set */, created_at)
                                                                              -- index (user_id, created_at)
favorites(user_id, headword, dict_id, note, created_at, updated_at, PRIMARY KEY(user_id, headword, dict_id))

dictionaries(id PRIMARY KEY,           -- PXDict's own stable id (also the folder name under DICT_DIR)
             wudict_id,                -- wuDict's id = sha256(path)[:12]; changes when originals are
                                       -- deleted or files move, so refreshed on every rescan
             wudict_uuid,              -- `uuid` from db/<name>/info.txt: stable, used to re-match
             library_dir,              -- db/<name>/ (wuDict appends " (fmt)" on name clashes)
             title, format, source CHECK(source IN ('builtin','proposal')),
             visibility CHECK(visibility IN ('global','private','hidden')),
             owner_user_id NULL,       -- for visibility='private'
             trusted_render BOOLEAN,   -- allows style-A rendering
             source_path, source_bytes, index_bytes, media_packed BOOLEAN, source_deleted_at,
             proposal_id NULL, created_at, updated_at)
user_dicts(user_id, dict_id, enabled, position, is_new, created_at, PRIMARY KEY(user_id, dict_id))
                                       -- filled in lazily (ADR 0007)

proposals(id, user_id, title, description, source_url, license_note,
          status CHECK(status IN ('uploading','pending','approved','rejected','withdrawn')),
          total_bytes, file_count, review_note, reviewed_by, reviewed_at,
          approved_scope CHECK(approved_scope IN ('global','private')), created_at)
proposal_files(proposal_id, rel_path, bytes, sha256, kind)                  -- kind: mdx|mdd|css|js|zim|other

audit_log(id, actor_user_id, action, target_type, target_id, details_json, bytes_freed, created_at)
```

`/data` layout:

```text
/data/dictionaries/<dict>/   approved dictionaries, scanned by wuDict (DICT_DIR)
/data/db/                    wuDict indexes (DB_DIR): <name>/{text.db,media.db,fulltext.db,info.txt}
/data/.wudict/{config,data,state,home}   wuDict XDG folders (HOME must not be /data, see notes Q12)
/data/gateway/pxdict.db      gateway data
/data/proposals/<id>/        upload quarantine (outside DICT_DIR)
/data/tmp/                   in-progress uploads, cleaned periodically
```

## 2. Gateway API (`/app-api`; request/response schemas in `shared/src/api/`)

| Group | Endpoints | Access |
|---|---|---|
| Auth (Better Auth, `/app-api/auth/*`) | sign-in/sign-up (email, username), social + OIDC callbacks, passkeys, magic link, email OTP, two-factor, sessions list/revoke, change password, admin user management. Endpoint shapes are Better Auth's | public / user / admin |
| Auth (PXDict) | `GET /auth/methods` (enabled sign-in methods + registration mode, for the login screen), `POST /auth/invite {code}` (remember an invite code for the next sign-up), `GET /me` (user + role + settings + new dictionaries) | public / user |
| History | `GET /me/history?q=&cursor=&limit=&unique=`, `GET /me/history/export?format=csv\|json`, `DELETE /me/history/{id}`, `DELETE /me/history` | user |
| Settings | `GET/PUT /me/settings` | user |
| My dictionaries | `GET /me/dicts` (allowed list + enabled + order), `PUT /me/dicts`, `POST /me/dicts/seen` (acknowledge new dictionaries) | user |
| Favorites | `GET /me/favorites`, `POST /me/favorites {headword, dictId, note?}`, `DELETE /me/favorites?headword=&dict=`, `GET /me/favorites/export?format=csv\|json` | user |
| Proposals | `POST /proposals` (multipart, size-limited), `GET /me/proposals`, `DELETE /proposals/{id}` (while pending) | user |
| Admin: users | Better Auth `admin` plugin endpoints (list, create, set role, ban/unban, revoke sessions, set password, impersonate, remove) + PXDict `GET/POST/DELETE /admin/invites` | admin |
| Admin: proposals | `GET /admin/proposals`, `GET /admin/proposals/{id}`, `POST .../{id}/approve {scope, dict_id, trusted_render}`, `POST .../{id}/reject {note}` | admin |
| Admin: dictionaries | `GET /admin/dicts`, `PATCH /admin/dicts/{id}` (visibility, trusted_render, title), `POST /admin/dicts/rescan`, `GET /admin/dicts/{id}/index-status` | admin |
| Admin: storage | `GET /admin/storage` (overview), `POST /admin/storage/plan` (dry-run → items + bytes + `plan_id`), `POST /admin/storage/execute {plan_id}` | admin |
| Admin: misc | `GET /admin/audit`, `GET /admin/system` (wuDict version, RAM, disk) | admin |
| System | `GET /healthz` (gateway + wuDict) | public |

Proxying to wuDict (after the session check):

| Path | Gateway behaviour |
|---|---|
| `GET /api/dicts` | NDJSON stream. Keep only dictionaries the user may use (`visibility`), add PXDict's `dictId`, title (as `name`), `enabled` and `trustedRender`, drop the builtin `wudict-howto`, **strip filesystem fields** (`path`, `dbPath`, `source`, `mediaSrc`, `textDB`, `mediaDB`, `folder`) |
| `GET /api/search`, `GET /api/suggest` | Always pass an explicit `dict=<id>,<id>,…` (never `all`; wuDict supports it on both): the user's enabled dictionaries in `position` order, or the requested ones the user may use. Empty set → answer empty without calling wuDict (an all-unknown list is a wuDict 404). Forward NDJSON lines as they arrive, names replaced by PXDict titles. Log `search_history` (`search` only, if enabled) |
| `GET /res/{dict}/…` | Check the user may access `{dict}`; sandboxed iframes use signed URLs (see Phase 4). wuDict already rewrites every resource reference to absolute `/res/{id}/…`, so the gateway rewrites only that prefix |
| `/style/*`, `/files/*`, `/assets/*` | **Not proxied**: Phase 0 found entry HTML never references them (wuDict's own UI only) |
| Everything else (`/setup`, `/api/library…`, `/api/ingest`, `/api/rescan`, …) | **404 for users**; admins only via `/app-api/admin/*` (optional: `/wudict-admin/*` for admins to use the native UI) |

For every proxied request the gateway removes the client's `Cookie`, `Authorization` and any `k` query
parameter (wuDict accepts its token from a cookie, Bearer or `?k=`), and drops `Set-Cookie` from
wuDict responses. wuDict answers 401 without a token, 421 for unknown `Host` names, and 403 for
`Sec-Fetch-Site: cross-site` outside its three extension routes.

## Phase 2 — Gateway foundation & a runnable image

**Goal:** one container running wuDict + gateway; the gateway serves the PWA and proxies wuDict safely.
No users yet (Phase 3 locks everything behind a bootstrap admin).

- [x] `config.ts`: add `AUTH_TOKEN` (required, ≥ 32 chars, never logged), `PUBLIC_URL`, `COOKIE_SECURE`, `REGISTRATION=closed|invite|open`, `MAX_UPLOAD_BYTES` (accepts `500MB`, `2GiB`), `MAX_PENDING_PROPOSALS_PER_USER`, `HISTORY_DEFAULT_RETENTION_DAYS`, … with validation, defaults, and every problem reported at once.
- [x] `db/`: open SQLite with `better-sqlite3` (WAL, `busy_timeout`, `foreign_keys=ON`), Drizzle client, run `drizzle-kit` migrations at startup; first migration with the PXDict tables of section 1 that do not depend on users (`dictionaries`, `audit_log`).
- [x] `wudict/`: client with timeouts; streaming proxy (Hono + `fetch` with `duplex: "half"`, body piped without buffering) injecting Bearer, setting Host, passing SSE **and NDJSON** through line by line, stripping client `Cookie`/`Authorization`/`?k=` and upstream `Set-Cookie`; route allowlist in `routes.ts` (with per-route query allowlists); reserved wuDict paths answer 404 instead of the SPA fallback; NDJSON filter for `/api/dicts` (drop `wudict-howto`, strip filesystem fields); `fake.ts` for tests.
- [x] Serve the static PWA from `/srv/pwa`: SPA fallback, `no-cache` for `sw.js`/`index.html`/`manifest.webmanifest`, `immutable` for `/app-assets/*`, precompressed or on-the-fly gzip/br.
- [x] Default security headers: CSP, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`.
- [x] `Dockerfile`, 3 stages: Node build (`node:26-alpine`: `npm ci`, build PWA + gateway bundle, `npm ci --omit=dev -w @pxdict/gateway` for native modules) → wuDict **purego build from source** at `WUDICT_VERSION` from `WUDICT_REPO=wuweidict/wudict` ([ADR 0002](adr/0002-build-wudict-from-source.md)) → `node:26-alpine` runtime + `tini`, UID 1000, V8 heap capped (`--max-old-space-size`).
- [x] `docker/entrypoint.sh`: check required env, generate `AUTH_TOKEN` if unset, create `/data/*`, start wuDict (`AUTH=on`, `SERVER_IP=127.0.0.1`, `USE_CACHED=1`, `INDEX_WORKERS=1`, `HOME`/`XDG_*` under `/data/.wudict/`) and gateway, `wait -n` → if one dies, stop the container (logic of original §3.2).
- [x] `HEALTHCHECK` calls the gateway's `/healthz` (which checks wuDict).
- [x] `scripts/smoke-test.sh`: run the image, wait for healthy, check `/`, `/manifest.webmanifest`, `/healthz`, wuDict only on loopback, non-allowlisted routes return 404.
- [x] Contract tests (Vitest) against the real wuDict binary (separate CI job that builds/downloads it).

**Done when:** `docker run` of a local image serves the empty PWA, `/api/search` through the gateway returns results, `/setup` returns 404.

**Result:** `scripts/smoke-test.sh pxdict:dev` checks exactly that (with a generated DSL dictionary),
plus loopback-only wuDict and no token in the logs; CI builds the image and runs it, and runs the
contract tests against a purego wuDict built at the pinned tag. Choices made on the way:

- Until Phase 5 the allowed dictionaries are "everything wuDict lists except `wudict-howto`"
  (`WudictCatalog`, cached for 5 s and revalidated with the `/api/dicts` etag). The proxy still always
  sends an explicit `dict=` list. `begin.total` and `end.etag` are removed from `/api/dicts` (they
  describe wuDict's whole library); DictInfo fields are allowlisted rather than stripped, and error
  strings from wuDict become generic (they can name files).
- `/api/search` refuses `format=clean` (wuDict would rewrite links to its loopback URL). `/res/…`
  answers with `Cache-Control: private`, a `sandbox` CSP (a resource opened as a page gets an opaque
  origin) and `Cross-Origin-Resource-Policy: cross-origin` (sandboxed iframes have an opaque origin).
- The runtime image copies only the `better-sqlite3` package (its N-API prebuild for the target
  architecture) instead of running `npm ci --omit=dev`: the bundle needs nothing else, and no compiler
  is needed anywhere because better-sqlite3 ships musl prebuilds.
- The PWA build writes `.br`/`.gz` next to compressible files; the gateway serves them precompressed
  and does not compress on the fly. A minimal `manifest.webmanifest` + SVG icon exist until
  `vite-plugin-pwa` (Phase 4).
- The entrypoint generates `AUTH_TOKEN` per start (nothing outside the container needs it) and
  redacts it from wuDict's output, whose startup banner prints its access key.

## Phase 3 — Authentication & user management

**Goal:** PXDict manages its own users with several sign-in methods; user/admin roles; admins manage
users. Every route except the login page, static assets, `/healthz`, `GET /app-api/auth/methods` and
Better Auth's public endpoints requires a session.

**Better Auth setup (`gateway/src/auth/`)**
- [x] Better Auth with the Drizzle adapter on `pxdict.db`; generate its schema with the Better Auth CLI and add it as a migration. `basePath: "/app-api/auth"`, `baseURL = PUBLIC_URL`, `trustedOrigins = [PUBLIC_URL]`, secret `BETTER_AUTH_SECRET` (required, ≥ 32 chars; the entrypoint generates and persists one under `/data/gateway/` if unset).
- [x] Sessions: cookie prefix `pxdict`, `HttpOnly`, `Secure` per `COOKIE_SECURE`, `SameSite=Lax`, 30-day sliding expiry (suits installed PWAs), cookie cache for fewer DB reads (60 s; admin routes always read the database, [ADR 0005](adr/0005-authentication-details.md)).
- [x] Rate limiting: Better Auth limiter with `storage: "database"`, stricter rules for sign-in, sign-up, password reset, magic link and OTP sending. The client address comes from the gateway (TCP peer or `CLIENT_IP_HEADER`), not from client headers.
- [x] Origin-check middleware for PXDict's own state-changing `/app-api` routes (same rule as Better Auth: `Origin` ∈ `trustedOrigins`, or `Sec-Fetch-Site: same-origin`); it also runs in front of Better Auth's routes, which check only requests with cookies (login CSRF), except the OAuth callback.
- [x] Guards: `requireUser`, `requireAdmin` (Hono middleware using `auth.api.getSession`), user in context; banned users are rejected.

**Sign-in methods** (each enabled by env; `GET /app-api/auth/methods` tells the PWA which ones)
- [x] Email **or username** + password (`emailAndPassword` + `username` plugin); minimum length + Have I Been Pwned check (`haveibeenpwned` plugin, optional `AUTH_HIBP=1`).
- [x] **Passkeys** (`@better-auth/passkey`): register from settings, sign in without a password; `rpID` derived from `PUBLIC_URL`; `AUTH_PASSKEY=false` turns them off. Server side done and tested up to the WebAuthn options; the ceremony itself is checked in a browser with the Phase 4 UI.
- [x] **Social providers:** Google, GitHub, Microsoft, Apple, Discord, Facebook, GitLab (each enabled when `AUTH_<PROVIDER>_CLIENT_ID` + `_CLIENT_SECRET` are set).
- [x] **Generic OIDC** (`generic-oauth`): one or more providers via `AUTH_OIDC_<NAME>_ISSUER`, `_CLIENT_ID`, `_CLIENT_SECRET`, `_LABEL` (Authentik, Keycloak, Zitadel, Authelia, …).
- [x] **Email**: optional SMTP (`SMTP_URL`, `MAIL_FROM`, via `nodemailer`). When set: email verification, password reset by email, **magic link** and **email OTP** sign-in. When unset: these are hidden and password resets are done by an admin.
- [x] **Two-factor (TOTP + backup codes)** (`two-factor` plugin), optional per user; `AUTH_REQUIRE_2FA_ADMIN=1` forces it for admins.
- [x] Account linking: a social/OIDC sign-in links to an existing user only when the provider reports a verified email matching it; users can link/unlink methods in settings (never remove the last one).

**Registration & admin**
- [x] Registration modes applied to **every** method (database hook on user creation): `closed` (admins create users), `invite` (single-use, expiring codes in `invites`, handed over in a short-lived cookie by `POST /app-api/auth/invite` so every method works the same, [ADR 0005](adr/0005-authentication-details.md)), `open` (rate-limited).
- [x] Admin bootstrap: if no admin exists, create one from `ADMIN_EMAIL` (+ optional `ADMIN_USERNAME`) + `ADMIN_PASSWORD`, or print a one-time random password to the log. Rescue CLI: `node pxdict-gateway.mjs user reset-password <email|username>`.
- [x] Admin (`admin` plugin): list/search users, create, change role, ban/unban (revokes sessions), reset password, revoke sessions, impersonate (audited), delete (removes history and favorites; proposals reassigned to admin or deleted — ask at delete time). Sessions, accounts, passkeys and 2FA go with the user; later per-user tables must cascade on `user.id`, and the proposal question is asked once proposals exist (Phase 6).
- [x] The last admin cannot demote, ban or delete themselves.
- [x] `audit_log` for every admin action and for bursts of failed sign-ins (Better Auth hooks).
- [x] Tests: each enabled method's happy path (OAuth/OIDC against a mocked provider), wrong password, rate limiting, origin check, registration modes, banned users, admin authorization, expired sessions. (OIDC against a local mock provider; GitHub through a stubbed `fetch`.)

**Done when:** the smoke test confirms `/api/search` returns 401 without a session and 200 after sign-in; a regular user gets 403 on `/app-api/admin/*`; password, passkey and one OIDC provider sign-in work in a browser.
The first two are in `scripts/smoke-test.sh`; browser sign-in needs the Phase 4 login screen (password
and OIDC are covered end to end by the gateway tests, passkeys only up to the WebAuthn options).

## Phase 4 — PWA MVP: lookups

**Goal:** usable every day on a phone.

- [x] Login screen driven by `GET /app-api/auth/methods`: password (email or username), passkey button (conditional UI / autofill), one button per social/OIDC provider, magic link / email code when SMTP is on, two-factor step; register / invite code when enabled; Better Auth's vanilla client (`better-auth/client`) wrapped in `src/api/app.ts`. Global 401 handling → back to login, keeping the pending query.
- [x] Account settings: change password, manage passkeys, linked accounts, two-factor, active sessions.
- [x] Search box + debounced suggestions, search `mode`, keyboard shortcuts, Android `share_target` pre-filling `q`.
- [x] Multi-dictionary results (collapsible per dictionary, ordered by the user's settings). The order is the gateway's slot order; Phase 5 makes it the user's.
- [x] **Style-B rendering**: iframe `sandbox="allow-scripts"` (+ `allow-popups` if needed), `postMessage` height sync, intercept internal links (`entry://`, `bword://`, `sound://`), play audio in the parent frame. The frame loads `/frame.html` (own CSP) instead of `srcdoc`, which would inherit the PWA's CSP ([ADR 0006](adr/0006-article-rendering-and-offline.md)).
- [x] Resources in a sandboxed iframe carry no cookie → the gateway issues **signed URLs** for `/res/`: `/r/<token>/<dict>/<path>` where token = HMAC(user_id, dict, short expiry); the gateway rewrites the `/res/<id>/` prefix in entry HTML before returning it (wuDict emits only absolute `/res/<id>/…` references; relative `url()` inside CSS then stays under the signed prefix). Audio is a plain `<a href="/res/…/x.mp3">` (from `sound://`): intercept by extension.
- [x] Style A (same-origin, modelled on wuDict's `frame.js`) only for dictionaries with `trusted_render = true`. The gateway sends `trustedRender` per dictionary; it is always false until admins can set it (Phase 6).
- [x] `vite-plugin-pwa`: manifest, icons, `registerType: "prompt"`, `navigateFallbackDenylist` covering `/api`, `/res`, `/r`, `/app-api`; runtime caching as in original §6.2 but **cache names include the user id**; logout wipes the user's caches + IndexedDB. Custom service worker (`injectManifest`, `pwa/src/sw/sw.ts`); sandboxed frames bypass it, so their offline copy comes from the HTTP cache (ADR 0006).
- [x] i18n (en source, vi), light/dark theme.
- [ ] Test on Android Chrome and iOS Safari (cookies in an installed PWA, passkey ceremony, offline lookups through the HTTP cache, ADR 0006).

**Done when:** PWA installed on Android + iOS, login works, lookups show images/audio, previously looked-up words are viewable offline.

## Phase 6 — Dictionary proposals & admin review

**Goal:** users propose new dictionary files; an admin reviews them before they can be used.

**User side**
- [ ] Proposal form: title, description, source URL, license note, files (`.mdx` + `.mdd`, `.css`, `.js`, images; or one `.zip`; other formats per the list confirmed in Phase 0).
- [ ] Stream uploads into `/data/tmp/`, enforce `MAX_UPLOAD_BYTES`, compute SHA-256 while writing, chunked/resumable uploads for large files; move into `/data/proposals/<id>/` only when complete.
- [ ] Quotas: pending proposals per user, total pending bytes system-wide; refuse when free disk is below a threshold.
- [ ] Users see the status of their proposals and can withdraw while `pending` (files deleted immediately).

**Automatic checks on receipt**
- [ ] Safe file names (no `..`, no absolute paths, no symlinks), extension allowlist.
- [ ] Zip: limits on entry count, total uncompressed size, compression ratio (zip-bomb protection).
- [ ] Read format headers (MDX: version, headword count, encoding) to show the admin; warn if JS is present.
- [ ] Duplicate detection: SHA-256 matching an existing dictionary or another proposal.

**Admin side**
- [ ] Proposal list (filter by status) and detail: proposer, files, sizes, hashes, metadata, warnings.
- [ ] **Preview before approval**: `wudict ingest` works on a separate library while the main server runs (different `SERVER_PORT`/`DB_DIR`), so a temporary instance is feasible; but an index built at a staging path is **not** reused after the move (absolute paths must match) — budget a second ingest, or use the `hidden` fallback below. Option A: index into a separate staging directory with a temporary wuDict instance and try lookups in a sandboxed iframe. If not feasible: approve as `hidden`, let the admin try it, then switch to `global`.
- [ ] Approve: choose `dict_id`, scope `global` (all users) or `private` (proposer only), `trusted_render` flag (off by default) → move files into `/data/dictionaries/<dict_id>/` (same-filesystem rename), `GET /api/rescan` (new files are not auto-detected), find the row by path, create the `dictionaries` row, **explicitly** `GET /api/ingest?dict=<id>&media=1` (SSE `progress`/`done`/`error`) before users can search it (search-before-index costs ~2.5× the RAM), record `wudict_uuid` from `info.txt`, surface indexing errors.
- [ ] Reject: record a reason, **delete files immediately** (free disk), keep metadata so the user sees the reason.
- [ ] Notify the user in the PWA when a proposal is approved/rejected.
- [ ] Catalogue sync: a "rescan" action (`GET /api/rescan`) reconciles `/data/dictionaries` + `/api/dicts` with the `dictionaries` table and records `wudict_uuid` from `info.txt`. The sync itself runs since Phase 5 on every listing change: dictionaries copied in manually → `source='builtin'` with `BUILTIN_DICT_VISIBILITY` (`global` by default; `hidden` keeps them back until an admin enables them, [ADR 0007](adr/0007-per-user-dictionaries-and-history.md)).

**Done when:** a user proposes a small MDX → the admin reviews and approves it as `global` → every user sees it and can look words up; a rejected proposal leaves no files on disk.

## Phase 7 — Storage administration

**Goal:** admins see where disk space goes and safely delete what is not needed.

- [ ] `GET /admin/storage`: free space on the volume; usage per area (`dictionaries`, `db`, `proposals`, `tmp`, `gateway`); per dictionary: original files, index, number of users with it enabled.
- [ ] Deletable categories:
  - **Original files of an indexed dictionary** — Phase 0 confirmed for **MDX/MDD only**, and only once media is packed (`media.db`) and wuDict runs with `USE_CACHED=1`: `DELETE /api/library?dict=<id>&prepared=0`. Sidecar files (CSS/JS beside the MDX) are left by wuDict → the gateway removes them. The wuDict id **changes** afterwards → rescan and re-match by `wudict_uuid`. Other formats: hidden with an explanation. Warning: without originals, the dictionary cannot be re-indexed when wuDict bumps its reader version.
  - **Whole dictionary (originals + index)** — removed from the system; warns how many users use it.
  - **Rejected / withdrawn proposals** with leftover files.
  - **Stale uploads** in `/data/tmp` older than 24 hours.
  - **Orphaned indexes** in `/data/db` with no matching dictionary.
  - **Unused auxiliary files** (e.g. duplicate `.mdd`, junk in dictionary folders) — listed only; the admin picks files individually.
- [ ] Two-step flow: `POST /admin/storage/plan` (dry-run returning paths, bytes, warnings, `plan_id` valid for 10 minutes) → `POST /admin/storage/execute {plan_id}`; execution re-checks every file (skips anything that changed) and writes `audit_log` with `bytes_freed`.
- [ ] Deleting a dictionary calls `DELETE /api/library?dict=<id>` first (removes `db/<name>/` + main/companion files; no dry run there, so the gateway builds its own), then cleans the remaining files in `/data/dictionaries/<dict_id>/`; updates `dictionaries` and `user_dicts`.
- [ ] Detect a read-only `DICT_DIR` mount → disable original-file deletion and say why.
- [ ] Gateway background jobs: clean `tmp`, expire history, weekly SQLite `VACUUM` (when idle).
- [ ] Admin UI in the PWA (`/admin`, visible to admins only): Users, Proposals, Dictionaries, Storage, Audit log.

**Done when:** an admin deletes a 500 MB dictionary via the UI, free disk increases accordingly, the audit log is correct; a dry-run never deletes anything.

## Key risks

| Risk | Impact | Mitigation |
|---|---|---|
| ~~wuDict cannot filter search by dictionary~~ | — | Resolved in Phase 0: `dict=` on `/api/search` and `/api/suggest` |
| wuDict needs originals after indexing | Cannot delete originals to save space | Phase 0: not needed for MDX/MDD after media packing; other formats hidden until verified |
| wuDict ids change when files move or originals are deleted | Broken references in user data | Gateway uses its own ids; re-match via `wudict_uuid` on every rescan |
| wuDict stops building purego / needs a newer Go | Image build fails | CI blocks the update; previous image stays; bump the Go stage |
| Better Auth breaking change or vulnerability | Sign-in broken or exposed | Exact version pin, upgrade PRs reviewed against its changelog, auth tests in CI, GitHub security advisories watched |
| Node.js RAM on a 1 GB VPS | Less headroom while wuDict indexes | V8 heap cap, swap, `INDEX_WORKERS=1`, index off-VPS |
| Sandboxed iframes break JS-heavy dictionaries | Broken rendering | Per-dictionary `trusted_render` flag set by admins |
| A malicious dictionary gets approved | Scripts attacking users/admins | Sandbox by default, JS warning at review, admin preview first |
| wuDict API changes without notice | Broken proxy / PWA | Contract tests + `tsc` in CI, pinned tags, roll back to the previous image |
| Large uploads through Cloudflare | HTTP 413 | Chunked uploads, or rsync for admins |
| Indexing large dictionaries on a small VPS | OOM | Swap, `INDEX_WORKERS=1`, index off-VPS (original §9.5) |
