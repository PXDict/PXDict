# Changelog

All notable changes to this project are documented here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added
- Project documentation: `AGENTS.md`, phased plan (`docs/PLAN.md`), original design archive, ADRs.
- Phase 0: verified wuDict v3.7.11 behaviour (`docs/wudict-notes.md`), ADR 0002 (build wuDict from
  source as purego), spike helpers in `scripts/spike/`, GPL-3.0-or-later `LICENSE`.
- Phase 1: npm workspace (`shared/`, `gateway/`, `pwa/`) with one ESLint config and lockfile; TypeScript
  gateway skeleton on Node.js + Hono (env config, `/healthz`, JSON error shape, JSON logs, graceful
  shutdown, esbuild bundle); `@pxdict/shared` zod contract and generated wuDict types (`npm run gen:api`);
  Preact + Vite + strict TypeScript PWA with Vitest and `en`/`vi` i18n; `scripts/dev.sh`; CI workflow;
  ADR 0003 (Preact).
- ADR 0004: the gateway is TypeScript and uses Better Auth for self-managed accounts with several sign-in
  methods (password, passkeys, social and OIDC providers, email link/code, two-factor).

- Phase 2: gateway configuration for every later phase (`AUTH_TOKEN`, `PUBLIC_URL`, `COOKIE_SECURE`,
  `REGISTRATION`, upload/proposal limits with byte sizes, history retention); SQLite database
  (`better-sqlite3`, WAL, Drizzle migrations at startup) with the `dictionaries` and `audit_log`
  tables; allowlisted streaming proxy to wuDict (`/api/dicts`, `/api/search`, `/api/suggest`,
  `/res/…`) with Bearer injection, header/query allowlists, an explicit `dict=` list, NDJSON filtering
  of filesystem fields and the builtin howto, and 404 for every other wuDict path; static PWA serving
  (precompressed files, cache headers, SPA fallback); default security headers; `/healthz` checks
  wuDict and the database; the `Dockerfile` (Node build → wuDict purego build → `node:26-alpine`
  runtime with `tini`), `docker/entrypoint.sh`, `scripts/smoke-test.sh`, contract tests against the
  real wuDict binary, and CI jobs for both.

- Phase 3: accounts with Better Auth 1.7 under `/app-api/auth` (schema generated by its CLI,
  `npm run auth:schema`): email or username + password (optional Have I Been Pwned check), passkeys,
  Google/GitHub/Microsoft/Apple/Discord/Facebook/GitLab and any OIDC provider (`AUTH_OIDC_<NAME>_*`),
  magic links, email codes, email verification and password reset when `SMTP_URL` is set, TOTP
  two-factor with backup codes (`AUTH_REQUIRE_2FA_ADMIN`), account linking only through verified emails;
  30-day sliding sessions in `pxdict`-prefixed cookies; database-backed rate limits keyed on a client
  address the gateway controls (`CLIENT_IP_HEADER`); the origin check on every state-changing
  `/app-api` request, Better Auth's included; registration modes for every method with invite codes
  (`/app-api/admin/invites`, `POST /app-api/auth/invite`); admin bootstrap from `ADMIN_*` (or a logged
  one-time password) and the `user reset-password` rescue CLI; user administration through Better Auth's
  admin plugin with the last-admin rule; `audit_log` entries for admin actions, invites, sign-ups and
  bursts of failed sign-ins; `GET /app-api/auth/methods` and `GET /app-api/me`; the wuDict proxy
  requires a session. The entrypoint generates and keeps `BETTER_AUTH_SECRET` in `/data/gateway/`.
  ADR 0005.

### Changed
- Reference wuDict version is v3.7.11 (v3.7.12 is only a pre-release).
- The first Go gateway skeleton was replaced by TypeScript; Cloudflare Access is no longer part of the
  design (PXDict accounts are the only login layer).
- Target runtime is Node.js 26 LTS (`.nvmrc`, `engines >=26.13.0`, esbuild target `node26`,
  `@types/node` 26, planned `node:26-alpine` image).
