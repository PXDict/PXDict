## [Unreleased]

### Added
- Project documentation: `AGENTS.md`, phased plan (`docs/PLAN.md`), original design archive, ADRs.
- Phase 0: verified wuDict v3.7.11 behaviour (`docs/wudict-notes.md`), ADR 0002 (build wuDict from
  source as purego), spike helpers in `scripts/spike/`, GPL-3.0-or-later `LICENSE`.
- Phase 1: npm workspace (`shared/`, `gateway/`, `pwa/`) with one ESLint config and lockfile; TypeScript
  gateway skeleton on Node.js + Hono (env config, `/healthz`, JSON error shape, JSON logs, graceful
  shutdown, esbuild bundle); `@pxdict/shared` zod contract and generated wuDict types (`npm run gen:api`);
  Preact + Vite + strict TypeScript PWA with Vitest and `en`/`vi` i18n; `scripts/dev.sh`; CI workflow;
  ADR 0003 (Preact).
- ADR 0004: the gateway is TypeScript and uses Better Auth for self-managed accounts with several sign-in
  methods (password, passkeys, social and OIDC providers, email link/code, two-factor).

- Phase 2: gateway configuration for every later phase (`AUTH_TOKEN`, `PUBLIC_URL`, `COOKIE_SECURE`,
  `REGISTRATION`, upload/proposal limits with byte sizes, history retention); SQLite database
  (`better-sqlite3`, WAL, Drizzle migrations at startup) with the `dictionaries` and `audit_log`
  tables; allowlisted streaming proxy to wuDict (`/api/dicts`, `/api/search`, `/api/suggest`,
  `/res/…`) with Bearer injection, header/query allowlists, an explicit `dict=` list, NDJSON filtering
  of filesystem fields and the builtin howto, and 404 for every other wuDict path; static PWA serving
  (precompressed files, cache headers, SPA fallback); default security headers; `/healthz` checks
  wuDict and the database; the `Dockerfile` (Node build → wuDict purego build → `node:26-alpine`
  runtime with `tini`), `docker/entrypoint.sh`, `scripts/smoke-test.sh`, contract tests against the
  real wuDict binary, and CI jobs for both.

- Phase 3: accounts with Better Auth 1.7 under `/app-api/auth` (schema generated by its CLI,
  `npm run auth:schema`): email or username + password (optional Have I Been Pwned check), passkeys,
  Google/GitHub/Microsoft/Apple/Discord/Facebook/GitLab and any OIDC provider (`AUTH_OIDC_<NAME>_*`),
  magic links, email codes, email verification and password reset when `SMTP_URL` is set, TOTP
  two-factor with backup codes (`AUTH_REQUIRE_2FA_ADMIN`), account linking only through verified emails;
  30-day sliding sessions in `pxdict`-prefixed cookies; database-backed rate limits keyed on a client
  address the gateway controls (`CLIENT_IP_HEADER`); the origin check on every state-changing
  `/app-api` request, Better Auth's included; registration modes for every method with invite codes
  (`/app-api/admin/invites`, `POST /app-api/auth/invite`); admin bootstrap from `ADMIN_*` (or a logged
  one-time password) and the `user reset-password` rescue CLI; user administration through Better Auth's
  admin plugin with the last-admin rule; `audit_log` entries for admin actions, invites, sign-ups and
  bursts of failed sign-ins; `GET /app-api/auth/methods` and `GET /app-api/me`; the wuDict proxy
  requires a session. The entrypoint generates and keeps `BETTER_AUTH_SECRET` in `/data/gateway/`.
  ADR 0005.

- Phase 4: the PWA for daily use. Login screen driven by `GET /app-api/auth/methods` (password with
  email or username, passkey button and autofill, social/OIDC buttons, magic link, email code, two-factor
  step, registration with invite codes, password reset page) on Better Auth's browser client; global 401
  handling back to login with the pending page kept; account settings (password, passkeys, linked
  accounts, TOTP two-factor with a QR code and backup codes, signed-in devices, language and theme);
  search box with debounced suggestions, search modes, `/` and Ctrl/Cmd+K shortcuts and an Android share
  target; streamed multi-dictionary results with lemma, skipped, deferred and failed dictionaries shown.
  Articles render in `/frame.html` (own CSP) in an opaque-origin sandbox, or same-origin for
  `trustedRender` dictionaries, with `postMessage` height sync, cross-reference lookups, audio played in
  the page and external links in a new tab. The gateway signs article resource URLs
  (`/r/<token>/<dict>/<path>`, HMAC, 1–2 h) and serves them without a session. `vite-plugin-pwa`
  service worker with per-user caches for lookups, resources and the dictionary list, wiped on logout;
  update prompt; PNG and maskable icons. `GET /app-api/me` returns the session id. ADR 0006.

- Phase 5: per-user features. The gateway keeps its `dictionaries` table in step with wuDict's listing
  (PXDict ids survive wuDict id changes; new dictionaries found on disk get `BUILTIN_DICT_VISIBILITY`,
  `global` by default) and per-user `user_dicts` (enabled flags, order, "new" notices). The proxy
  searches each user's enabled dictionaries in their order and names them with PXDict's titles.
  Search history is recorded by the proxy (repeats within a minute merged), can be filtered, deleted
  and exported as CSV/JSON, and is trimmed hourly by each user's retention. Favorites (with notes,
  export) and per-user settings (history, retention, default search mode, language, theme, text size)
  are under `/app-api/me/*`, with `settings` and `newDicts` in `GET /app-api/me`. The PWA adds History,
  Saved words and Dictionaries screens (toggle, drag-and-drop and arrow ordering), a ☆ button per
  headword, recent searches in the empty search box, a new-dictionary notice, and preferences saved to
  the account; article frames follow the text size. HTTP isolation tests between users. ADR 0007.
- Phase 6: dictionary proposals and admin review (ADR 0008). Users propose a dictionary (metadata +
  files, or one `.zip`); files upload in resumable ≤ 32 MiB chunks (`Upload-Offset`) with SHA-256 while
  writing, quotas per user, for the review queue and for free disk, and stay in `/data/proposals/<id>/`
  until reviewed. On submit the gateway unpacks zips with zip-bomb limits (`yauzl`), checks names
  (`storage/safe-path.ts`: no traversal, hidden names or symlinks) and file types, reads MDX/DSL/StarDict
  headers, and warns about JavaScript, encryption and duplicates. Admins list and review proposals,
  reject them (files deleted at once, reason kept) or approve them as `global`, `private` or `hidden`:
  files move into `DICT_DIR`, wuDict rescans and indexes (`media=1`) in the background, and users see
  the dictionary only once it is indexed. Admins can try hidden dictionaries by name, change visibility,
  owner, title and trusted rendering, rescan, and retry indexing; the catalogue records the library
  `uuid` from `info.txt`. Proposers are notified of decisions in the PWA. New PWA screens: Propose,
  Admin → Proposals and Dictionaries. Contract test of the approval flow against the real wuDict.

- Phase 7: storage administration (`/app-api/admin/storage`, ADR 0009): disk use per area and per
  dictionary (original files, index, users who enabled it); deletion of MDX original files (index kept),
  whole dictionaries, leftover proposal files, stale temporary files, orphaned indexes and auxiliary
  files, always as a dry-run plan (every path and size, warnings, valid ten minutes) followed by an
  execution that re-checks every file and records `storage.delete` with `bytes_freed` in `audit_log`;
  read-only `DICT_DIR` detection; `GET /app-api/admin/audit`; hourly removal of stale `tmp/` entries and
  a weekly `VACUUM` when idle; the PWA's admin area gains Users (roles, suspend, sign out everywhere,
  delete, invite codes), Storage and Audit log pages.

### Changed
- Reference wuDict version is v3.7.11 (v3.7.12 is only a pre-release).
- The first Go gateway skeleton was replaced by TypeScript; Cloudflare Access is no longer part of the
  design (PXDict accounts are the only login layer).
- Target runtime is Node.js 26 LTS (`.nvmrc`, `engines >=26.13.0`, esbuild target `node26`,
  `@types/node` 26, planned `node:26-alpine` image).
